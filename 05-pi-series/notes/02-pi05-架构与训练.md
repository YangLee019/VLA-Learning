# 第 2 讲：π₀.₅ 的混合训练、共享模型高低层推理与开放环境泛化

> 依据 [π₀.₅ 论文 v1 §IV–V、附录 A-E](https://arxiv.org/html/2504.16054v1)与[本地 PDF](../papers/pi0.5_2504.16054v1.pdf)。先掌握[π₀ 的 flow matching](./01-pi0-架构与训练.md)。本讲把“模型是什么”“训练时见到什么监督”“部署时怎样调用”分开，避免把论文的多种数据说成一个模糊的“大数据集”。

## 1. 研究问题：新家庭中的长时序操作

π₀ 已能在多机器人任务中学习高频连续控制，却未解决“走进未见过的家庭，按抽象指令清理房间”这个组合问题。新家庭意味着新布局、背景、物体实例甚至类别；长任务需要在多次抓取、开关抽屉、移动底座之间选择下一步。π₀.₅ 的主张是把**跨机器人行为、跨场景数据、网页语义、对象定位、子任务预测与低层动作**合到一个模型训练配方，再用同一模型先做高层文本推断、后做低层动作采样。[论文 §I、§IV](https://arxiv.org/html/2504.16054v1)

“同一模型”不意味着一个前向同时输出整段规划和完整动作；它是**两种调用模式共享参数**。给总任务 $\ell$、当前观察 $o_t$，先生成子任务文字 $\hat\ell$，然后以 $\hat\ell$ 为条件生成动作块 $A_t$：

$$\pi_\theta(A_t,\hat\ell\mid o_t,\ell)=\pi_\theta(A_t\mid o_t,\hat\ell)\,\pi_\theta(\hat\ell\mid o_t,\ell).$$

论文的这个因子分解**明确假设低层动作只以子任务 $\hat\ell$ 而非原始总任务 $\ell$ 为语言条件**。这有利于把“收拾厨房”拆成“拿起盘子”等可执行步骤，却也让高层错误成为低层错误的来源。高层推断频率低于动作块调用频率。[论文 §III–IV-A](https://arxiv.org/html/2504.16054v1)

```mermaid
flowchart LR
    C[总任务：清理厨房] --> H[同一 VLM 模式：预测文字子任务]
    O[当前相机和状态] --> H
    H --> S[子任务：把盘子放进水槽]
    S --> L[同一模型 + 动作专家模式]
    O --> L
    L --> A[连续动作块]
    A --> E[执行一段并更新观察]
    E --> O
```

*图 1：论文部署中的高低层调用。并非把外部 LLM 接到一个完全独立的机器人策略；高层与低层来自同一训练模型。*

## 2. 架构：在 π₀ 基础上加入离散输出能力

VLM 主干仍以 PaliGemma 初始化；输入有多视角图像、任务文字、机器人状态。与 π₀ 的状态连续投影进入动作专家不同，π₀.₅ **将本体状态离散化成文本 token** 放在 VLM 前缀。它既可用词表头生成文字、对象位置/子任务，也可让约 300M 参数的动作专家从带噪连续动作块预测 flow 速度。论文附录称 VLM 与专家宽度分别 2048 与 1024，专家仍是较小的 Transformer；动作专家在后训练才加入。[论文 §IV-A、附录 A-E](https://arxiv.org/html/2504.16054v1#A5)、[官方模型配置](https://github.com/Physical-Intelligence/openpi/blob/main/src/openpi/models/pi0_config.py)

π₀.₅ 对 flow 时间 $\tau$ 的注入也与 π₀ 不同：π₀ 先把 $\tau$ 编码与噪声动作拼接并投影到专家输入；π₀.₅ 用时间 MLP，并在动作专家每层通过 **adaptive RMSNorm** 注入时间信息。这个细节表明“沿用 π₀ 的专家”主要指双专家结构与 flow 目标，不是每层实现完全不变。[论文附录 A-E](https://arxiv.org/html/2504.16054v1#A5)

### 注意力隔离：训练时两种动作监督不能互相偷看

后训练同时有词表中的 FAST 动作 token 与连续 flow 动作 token，若它们互相可见，模型可能直接抄同一标签的另一种表示，训练损失低却破坏推理。论文通过 mask 隔离：图像、提示和状态组成可双向可见的前缀；FAST token 自回归看前缀及先前 FAST token；连续动作专家看前缀和同一动作块的全部带噪动作槽，**不看 FAST 动作 token**。VLM 前缀也不看动作专家后缀，信息主要单向从 VLM 流向动作专家。[论文 §IV-B、附录 A-E/Fig. 18](https://arxiv.org/html/2504.16054v1#A5)

| 查询位置 | 观察与文字前缀 | 以前的 FAST token | 全部带噪动作槽 |
| --- | :---: | :---: | :---: |
| 前缀 | ✓ | × | × |
| FAST token | ✓ | ✓ | × |
| 连续动作专家 | ✓ | × | ✓ |

这个表是论文 mask 的教学抽象；具体同一序列中状态、对象位置与子任务 token 的位置取决于训练样本类型。**不要**把 π₀.₅ 表述为“两个完全独立、互不共享的模型”或“动作专家阅读已生成的 FAST token 后做反量化”。[论文附录 A-E](https://arxiv.org/html/2504.16054v1#A5)

## 3. 为什么先离散预训练，再连续后训练

π₀ 在机器人预训练始终用 flow 动作专家。π₀.₅ 的**机器人阶段预训练**则先把所有动作块压缩成 FAST 离散 token，与文字、对象位置等任务一起做标准 next-token prediction；论文训练 **280k steps**。这样模型可沿用成熟的自回归训练路径，且一个预测词表可以承载机器人动作和语义监督。FAST 比逐维逐时步 256-bin 量化更适合高频动作块，原理见[第 3 讲](./03-FAST与研究对照.md)。[论文 §IV-B/C](https://arxiv.org/html/2504.16054v1)

进入**后训练**，随机初始化动作专家，联合优化文字/FAST 的交叉熵与连续动作 flow loss，约 **80k steps**，论文设置 flow 权重 $\alpha=10$。这既保留文字生成/语义能力，也提供更适合实时控制的连续动作输出。部署时先自回归生成高层文本，再对低层动作做约 10 步 flow 积分；并不是在每次控制周期先自回归生成完整 FAST 序列再让专家解码。FAST 主要是预训练与联合监督工具，flow 专家是最终低层动作采样路径。[论文 §IV-B/D](https://arxiv.org/html/2504.16054v1)

在机器人动作尺度上，论文使用**每个数据集、每个动作维度**的 1%/99% 分位点归一化至 $[-1,1]$，以固定最大动作宽度容纳多种机器人，低维动作零填充；用控制模式文本区分关节目标与末端目标。零填充仅解决张量形状，不自动解决关节顺序、单位、控制语义和损失掩码问题；部署仍须目标机器人的归一化统计与接口。[论文 §IV-C](https://arxiv.org/html/2504.16054v1)

### 两个原文符号核对点

1. π₀ 论文的路径写作 $A^\tau=\tau A+(1-\tau)\epsilon$，从 $\tau=0$ 噪声走到 1 数据，训练速度是 $A-\epsilon$。π₀.₅ 论文 §IV-B 仍写这条路径，却在式 (1) 将目标写成 $\omega-A$；**按印出的路径直接求导应是 $A-\omega$**。当前[openpi 训练与采样代码](https://github.com/Physical-Intelligence/openpi/blob/main/src/openpi/models/pi0.py)明确采用**反向时间约定**：$x^\tau=\tau\omega+(1-\tau)A$，$\tau=1$ 为噪声、0 为数据，目标 $\omega-A$，以负步长从 1 积分到 0。这样实现内部自洽。论文印出的路径与目标符号不一致；复现时须同时核对固定代码版本的路径、速度目标与积分方向，不能只照抄其中一个公式。[π₀ §IV](https://arxiv.org/html/2410.24164v4#S4)、[π₀.₅ §IV-B](https://arxiv.org/html/2504.16054v1)
2. π₀.₅ 附录 A-E 同一句写“action horizon of 50, i.e. $H=49$”，显然长度与索引口径混在一起。学习时按 **50 个动作时步**理解架构，并在实现时检查包含端点的索引和实际 `action_horizon` 配置，勿机械把 $H$ 写成 49。[π₀.₅ 附录 A-E](https://arxiv.org/html/2504.16054v1#A5)

## 4. 六种数据监督具体教会模型什么

| 缩写 | 数据来源/目标 | 训练阶段与主要作用 |
| --- | --- | --- |
| MM | 多家庭移动操作数据，约 400 小时、约 100 个家庭 | 预训练与后训练；最接近目标移动机器人任务 |
| ME | 多环境固定单臂/双臂数据 | 跨场景视觉与操作迁移；本体不同但家庭布局多样 |
| CE | 实验室多机器人、多任务数据，含 OXE | 丰富操作技能与本体变化；后训练不以该部分为主 |
| HL | 观测与总任务 → 子任务文字；也有人为对象框标注 | 让同一模型学会语义分解及对象定位 |
| WD | 网页图文 caption、VQA、对象定位 | 保持/扩展开放物体语义，尤其支持未见类别和高层推断 |
| VI | 人在真实机器人执行中用语言逐步指挥的演示 | 后训练高层决策，与低层策略实际可完成的步骤对齐 |

预训练用 MM、ME、CE、HL、WD；后训练聚焦成功且时长合适的 MM/ME 动作数据，保留 WD 与部分 HL，并加入 VI。简单说“π₀.₅ 有 400 小时数据”会遗漏跨机器人和网页监督；说“用了很多网页数据所以家庭成功”也忽略机器人技能和场景多样性。[论文 §IV-C/D](https://arxiv.org/html/2504.16054v1)

HL 的细节尤其重要：作者对多阶段机器人轨迹人工标注子任务描述，并标相关对象框，让模型学会“当前图像和总目标 → 当前合适子目标”。VI 则像真人在机器人执行时实时口头遥操作，产生对**已学低层策略可执行动作**更对齐的高层示范。这解释了为何后训练 VI 即便量小仍可能有用。[论文 §IV-C/D、§V-E](https://arxiv.org/html/2504.16054v1)

## 5. 实验如何支撑“开放环境泛化”

论文在未进入训练的新家庭和可控 mock 家庭测试。真实家庭评估覆盖三套厨房和三套卧室；有清理厨房、把物品放进抽屉、收衣物等任务，单次可持续数分钟。图 7 的指标是按任务 rubric 计算的**完成进度百分比**，例如完成若干子步骤得部分分，而非全任务二值成功率。论文还有 10–15 分钟的示例，但定量评价中许多任务为 2–5 分钟，不能把最长展示时长当成所有任务平均值。[论文 §V-A、附录 A-B](https://arxiv.org/html/2504.16054v1)

场景数量实验用 3、12、22、53、82、104 个训练地点，尽量控制样本数，未见 mock 环境表现总体随地点数上升。这里的实验**未对每个地点数量完整重跑 280k+80k 的全部配方**，而是用共同基础预训练后分别训练，因而应读作“在此受控设置下场景多样性的趋势”。测试家庭训练对照达到近似分数，说明有较好的环境外迁移，但不是“所有新家表现等于训练家”。[论文 §V-B](https://arxiv.org/html/2504.16054v1)

消融也有精细边界：去掉 ME/CE 在总体任务完成度上明显变差；去掉 WD 在 Fig. 10 总体任务得分差异未显著，却在未见物体的语言选择与高层推断上明显下降。不能笼统宣称网页数据对所有任务得分都显著，或宣称其完全无用。完整模型相较 π₀ 与“π₀-FAST+Flow”在 mock 家庭表现更好；后者共享类似离散/连续动作训练但不含 HL/WD，帮助识别多任务共同训练的价值，不过仍需留意不同阶段配方与模型训练历史。[论文 §V-C/D](https://arxiv.org/html/2504.16054v1)

高层实验中，完整模型最好；“implicit HL”（训练有 HL，部署不显式生成子任务）仍是强基线，说明**高层数据作为训练监督**与**部署时真的多调用一次高层推断**是两种不同收益。去掉 VI 或 WD 明显下降；用零样本 GPT-4 做高层在该设置较差，但不能一般化为所有外部 LLM 规划必定较差。[论文 §V-E](https://arxiv.org/html/2504.16054v1)

## 6. 局限与自测

论文报告对难开的抽屉/柜门、机械臂遮挡目标造成的部分可观测问题，以及高层反复开关抽屉等错误。真实家庭数量仍有限，且多项数据为私有；开放的 `openpi` 实现和检查点有助于研究复现，但不等同论文全部训练数据或全部实机条件。[论文 §VI](https://arxiv.org/html/2504.16054v1)、[官方代码](https://github.com/Physical-Intelligence/openpi)

1. **π₀.₅ 的高层与低层是两套完全独立的网络吗？** 不是；同一训练模型以不同模式预测文字子任务和连续动作，低层用动作专家。
2. **FAST 是否是最终实时动作输出路径？** 论文最终低层主要用 flow 专家；FAST 服务高效预训练及后训练联合监督。
3. **MM 与 ME 都来自家庭，为何还需要区分？** MM 是目标移动本体，ME 是不同的固定本体但场景多样，区分可检验跨本体/跨场景迁移。
4. **“去掉 WD 不显著”与“WD 帮助泛化”冲突吗？** 不冲突。前者是 Fig. 10 总体任务进度，后者是未见物体语言与高层决策指标。
5. **为什么真实家庭进度分不等于任务成功率？** rubric 可对部分完成给分，必须看分母、步骤及评测次数。
