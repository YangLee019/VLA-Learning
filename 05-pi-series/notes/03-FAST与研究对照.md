# 第 3 讲：FAST 动作 token、π₀→π₀.₅ 的研究对照与复盘

> 依据 [FAST 论文 v1 §III–VI](https://arxiv.org/html/2501.09747v1)、[π₀ v4](https://arxiv.org/html/2410.24164v4)、[π₀.₅ v1](https://arxiv.org/html/2504.16054v1)。FAST 原文见[本地 PDF](../papers/FAST_2501.09747v1.pdf)。本讲不是泛泛比较“离散和连续哪个好”，而是回答**训练计算、动作精度和部署延迟为什么会给出不同最优选择**。

## 1. 高频动作块为什么难用逐维 bin 自回归

若动作块有 $H$ 个时步、每步 $D$ 维，最朴素的逐维量化要生成约 $HD$ 个 token。以 $H=50,D=18$ 为例，约 900 个动作 token；即使每个 token 很容易预测，训练序列很长且推理必须串行。高频控制中相邻时步往往强相关，模型可通过复制前一个量化值降低 next-token loss，却未必真正学到任务条件下的动作轨迹。这是 FAST 论文的核心观察。[FAST §III–IV](https://arxiv.org/html/2501.09747v1)

**注意**：训练时因 teacher forcing，可以并行计算所有 token 的 logits，问题不只是“训练必须串行”。更关键的是长序列的 attention 成本、目标冗余以及模型容易学到局部复制捷径；测试时自回归解码延迟才真正具有串行依赖。OFT 选择直接并行连续头，FAST 则选择保留标准语言模型目标但改变动作序列的编码。[FAST §IV–V](https://arxiv.org/html/2501.09747v1)、[OFT 讲义](../../04-openvla-oft/notes/01-OFT架构与训练目标.md)

## 2. FAST 的完整编码和解码路径

```mermaid
flowchart LR
    A[H×D 连续动作] --> N[每维分位数归一化]
    N --> DCT[沿时间维分别做 DCT]
    DCT --> Q[系数缩放并取整]
    Q --> O[按频率排序交错各动作维]
    O --> B[BPE 压缩]
    B --> T[较短的离散动作 token 序列]
    T --> IB[逆 BPE]
    IB --> ID[逆量化与逆 DCT]
    ID --> R[近似重建的动作块]
```

*图 1：BPE 压缩的是离散余弦系数的整数序列；信息损失主要来自系数量化，不来自 BPE 本身。*

给第 $j$ 个动作维度的时间信号 $(a_{1,j},\ldots,a_{H,j})$，DCT 将其表示为各频率余弦基系数 $C_{k,j}$。平滑运动通常把较多能量集中在低频系数，高频系数更小。对每个系数做 $\bar C_{k,j}=\operatorname{round}(\gamma C_{k,j})$，小值变成 0，形成稀疏矩阵。**$\gamma$ 控制压缩率与重建误差**：越粗的取整越短但细节丢失越多。然后按**低频优先、各动作维交错**展开整数序列；BPE 学常见片段合并，包括大量连续 0 和常见跨维系数组合。[FAST §V-A/B、Algorithm 1](https://arxiv.org/html/2501.09747v1)

为什么是“低频先于高频”而不只是任意排序？自回归策略先生成决定轨迹整体形状的系数，再补局部细节；论文对照发现这种顺序的 rollout 更稳定。BPE 属于无损地压缩**已经量化后的整数序列**；逆 BPE 能恢复该整数序列，但逆 DCT 恢复不了取整前全部细节。因此“FAST 的全部变换都可逆”是过度表述。[FAST §V-B、§VI-D](https://arxiv.org/html/2501.09747v1)

FAST+ 是在约 **100 万个、一秒长的真实机器人动作块**上训练的通用 BPE 词表，覆盖单臂、双臂、移动操作、关节与末端控制。通用词表减少每个新数据集重新训练 tokenizer 的步骤；动作仍需按数据集统计归一化、保持控制语义一致。[FAST §V-C](https://arxiv.org/html/2501.09747v1)

FAST 论文报告：把它用于 π₀ 架构的自回归策略，在大规模数据上可与 flow 版 π₀ 接近，并将训练时间最多降低约 **5×**；小数据设置差距不一定大，大数据 Table Bussing 上 FAST 在更少训练步达到高表现。这些是论文的指定训练和任务设置，**5× 是训练时间对照，不是 π₀.₅ 在线动作延迟提升 5×**。若直接用 FAST 自回归输出动作，推理仍要依序生成压缩 token；这正是 π₀.₅ 后训练又加入 flow 专家的原因。[FAST §VI-E/F](https://arxiv.org/html/2501.09747v1)、[π₀.₅ §IV-B](https://arxiv.org/html/2504.16054v1)

## 3. 四条动作路线放在同一坐标上

| 方法 | 训练监督 | 推理动作生成 | 强项与主要代价 |
| --- | --- | --- | --- |
| 原版 OpenVLA | 每维离散 token CE | 单步动作，7 token 自回归 | 简单复用 LLM；高频长块成本大且量化粗 |
| OpenVLA-OFT | 连续动作块 L1 | 一次前向并行输出 | 低延迟、精确；多峰条件下点预测可能平均化 |
| π₀ | 连续动作块 flow loss | 专家多步积分，论文 10 步 | 能建模连续条件分布；每块多次专家前向 |
| π₀-FAST | DCT+BPE 动作 token CE | 压缩 token 自回归 | 大规模训练高效；在线仍有串行生成 |
| π₀.₅ | 预训练 FAST/文字 CE；后训练联合 CE+flow | 高层文字自回归，低层 flow 动作块 | 同时利用语义与高频控制；配方和评估更复杂 |

同样是“动作块”，这些模型的**预测长度、实际执行长度、重规划频率**各不相同；比较 Hz 前必须先查单次调用延迟与每次执行多少动作。[π₀ 附录 A-D](https://arxiv.org/html/2410.24164v4#A4)、[OFT Table II](https://arxiv.org/html/2502.19645)

## 4. π₀.₅ 的证据链：哪些变量被分开测了

| 问题 | 论文比较 | 可以得出的结论 | 不应过度推断 |
| --- | --- | --- | --- |
| 场景多样性是否有用？ | 训练地点 3→104，测未见 mock 家庭 | 更多地点总体提高任务进度和语言表现 | 并非全配方每个规模重训；也非无限场景的保证 |
| 跨本体数据是否有用？ | 去掉 ME、CE 或两者 | 新环境任务分数明显下降 | 不能说明任意外部机器人数据都等价有益 |
| 网页数据是否有用？ | 去掉 WD | 总体任务进度变化未显著，但未见物体语言与高层决策下降 | 不能只看一个总分就说 WD 无用 |
| 高层推理本身有用吗？ | full、implicit HL、no HL、no VI、GPT-4 HL | 显式高层有收益；高层训练数据本身也带来大部分收益 | 不证明外部规划器一般不如同模型 |
| π₀.₅ 是否胜过 π₀？ | π₀、π₀-FAST+Flow、π₀.₅ | 相近跨本体机器人数据条件下，完整配方在 mock 家庭更好 | 改动不仅一个：数据、动作预训练、高层共同变化 |

π₀.₅ 的 real-home 结果是**未见家庭中的任务完成进度**，不是统一二值成功率；四个 mock 任务以同一 rubric 做细粒度消融。论文附录指出标准对比每策略通常约 40 次评估；这是机器人真实交互实验，不宜把小样本结果解释成精确的普适成功率。[π₀.₅ §V、附录 A-B](https://arxiv.org/html/2504.16054v1)

## 5. 读者自己的研究判断

这三篇论文连起来呈现一个有张力的路线：**π₀ 证明连续 flow 专家和大规模机器人预训练可执行灵巧任务；FAST 证明压缩离散动作能大幅降低自回归 VLA 的训练难度；π₀.₅ 将离散高效预训练、语义共同训练与连续低层采样结合。** 这不是“新模型全面替代旧模型”的简单线性进步：π₀.₅ 主要解决的是跨新家庭的任务泛化，OFT 主要研究已有 VLA 的目标域微调效率，评价任务与数据不同。[π₀ §VII](https://arxiv.org/html/2410.24164v4)、[FAST §VII](https://arxiv.org/html/2501.09747v1)、[π₀.₅ §VI](https://arxiv.org/html/2504.16054v1)

若自己设计后续实验，可以固定 PaliGemma 主干、机器人数据、动作空间和在线评估，比较：(a) flow-only 预训练；(b) FAST-only 预训练 + flow 后训练；(c) 再加 HL/WD/VI。分别记录训练 GPU 小时、动作重建误差、每块推理延迟、未见物体语言选择与长任务进度。**这是可检验的研究设计建议，并非论文已完整做出的全因子消融。**

## 6. 带解析自测

1. **为何简单的 per-step CE 可能“低损失、差策略”？** 高频动作相邻 token 高相关，复制邻近值可降低 loss，却不必学习视觉和任务条件。
2. **DCT 和 BPE 各压缩了什么？** DCT 将时间相关性集中到低频；系数量化让许多项为 0；BPE 无损压缩量化后的整数序列中的重复片段。
3. **FAST 比逐维 bin 短，是否因此低层在线一定比 flow 快？** 不是。FAST 仍自回归；flow 虽 10 次专家前向，但专家小、前缀可缓存，实际延迟需测。
4. **π₀.₅ 的高层文字与低层动作各用何种目标？** 文字/FAST token 用 CE；低层连续动作专家用 flow loss。
5. **π₀.₅ 论文“未见家庭”是否等于所有对象、所有房屋零样本成功？** 不是。任务、机器人、家庭数量与进度 rubric 由论文限定，也报告机械困难、遮挡和高层循环错误。
